# 設定パネルをメモ操作で閉じる

## 概要
設定パネルまたはヘルプパネルを開いている間に、新しいメモを作成したり、一覧から既存のメモを開いたりしたら、パネルを閉じてメモ画面に戻す。未保存の設定変更は保存せず、現状どおり破棄する。

## 調査結果
- `src/memo.js` の `loadMemo` は本文・タイトル・一覧の更新とフォーカスだけを行い、設定／ヘルプパネルには触れていない（`src/memo.js:141`）。
- 新規メモは `createNewMemo` から `loadMemo` を呼ぶ（`src/memo.js:212`）。一覧の項目クリックも `loadMemo` を呼ぶ（`src/memo.js:135`）。
- 設定パネルとヘルプパネルは `setSettingsOpen` / `setHelpOpen` で排他的に開閉し、`syncMainVisibility` がタイトル行とエディタの表示を切り替える（`src/memo.js:377`、`src/memo.js:387`、`src/memo.js:398`）。
- 現状、パネルを開いたまま一覧のメモをクリックすると、裏で選択中のメモは変わるがパネルは開いたままになる。
- 設定の変更は `changeSettings` で画面に反映するだけで、`saveSettingsFromPanel`（保存ボタン）を押すまで `localStorage` には書かない（`src/memo.js:456`、`src/memo.js:473`）。

- [x] ステップ2: 一覧のメモ項目のクリックハンドラで、`loadMemo` の前に `closePanels()` を呼ぶ（`src/memo.js:135`）。

- [x] ステップ4: 全メモ削除や削除後の自動切り替えなど、依頼にない経路ではパネルを閉じないよう、`loadMemo` 自体には手を入れない（`src/memo.js`）。

## 決定事項
- メモを開いたときは、設定パネルだけでなくヘルプパネルも閉じる。
- パネルが自動で閉じるとき、未保存の設定変更は保存せず破棄する（保存ボタンを押したときだけ保存する現状の動作を維持する）。
- パネルを閉じる対象は、依頼にある「新規メモ作成」と「一覧からメモを開く」の2操作とする。全メモ削除などの設定パネル内の操作では閉じない。

## 懸念点・未決事項
- `loadMemo` は起動時・削除後の自動切り替えでも呼ばれるため、`loadMemo` 内で閉じると依頼外の動作も変わってしまう。クリックハンドラ側で閉じる方針にした。
- パネルを閉じたあとのフォーカスは既存の `loadMemo` の `contentInput.focus()` に任せる。閉じる処理がフォーカスを奪わないことを確認する。
