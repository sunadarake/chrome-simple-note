# 設定画面を作る

## 概要
メモ画面の中に設定パネルを作り、次の操作を集める。
- エクスポート／インポート（今の「☰」メニューから移す）
- 自動保存のオン／オフ
- 自動保存の間隔
- エディタの文字サイズ
- テーマ（ライト／ダーク）
- 通常メモの全削除

設定は `localStorage` に保存し、リロードしても保たれるようにする。

## 調査結果
- `src/memo.html`: サイドバー上部に `.sidebar-menu-btn`（☰）と `.sidebar-menu`（`.export-btn` / `.import-btn`）、`.import-input` がある。メイン画面は `.main-header`（タイトルと削除・コピー・保存）と `.editor`。
- `src/memo.js` の `initMemoApp`: エクスポート（`exportToFile`）、インポート（`importFromFile`）、メニュー開閉（`setMenuOpen`）を持つ。自動保存の待ち時間は定数 `AUTO_SAVE_DELAY_MS`（1000ms）で、`handleContentInput` が使う。
- `src/memo.css`: 文字サイズ 16px は `.editor-highlight` と `.content-input` に共通で指定している（両者を必ずそろえる。AGENTS.md の注意）。通常メモは白・グレー、シークレットは `.main-content.secret` 配下でダーク（`#2b2d31`）。
- `src/storage.js`: `memos` キーの読み書きのみ。`sidebarWidth` / `sidebarCollapsed` は `src/sidebar.js` が自前で `localStorage` を読み書きしている。
- `src/main.js`: `document` / `localStorage` / `sessionStorage` を渡して `initMemoApp` などを起動する。
- `src/memo.test.js`: 「サイドバーのメニュー」「エクスポート」「インポート」のテストが ☰ メニュー前提。移動に合わせて書き換えが必要。
- `manifest.json` に `permissions` は不要（`localStorage` のみ使う）。

## 決定事項
- 設定画面はメモ画面内のパネルにする（別ページにしない）。
- 「☰」メニューはなくし、歯車ボタンに置き換える。エクスポート／インポートは設定パネルだけに置く。
- 追加の設定は「自動保存の間隔」「エディタの文字サイズ」「テーマ（ライト／ダーク）」「全メモ削除」。
- 自動保存をオフにしたときは、保存ボタンだけで保存する。閉じる前の確認ダイアログは出さない。

- 設定パネルを開いている間は、サイドバーを閉じていると再度開く手段がない（メイン画面の「»」はタイトル行にあり隠れる）。パネルを閉じれば使える。
- ダークテーマの通常メモは中立の濃いグレー（`#1a1a1a`）、シークレットは青みのある `#2b2d31` で区別した。
- 全メモ削除の件数には、書き始める前の空メモを数えない。

## 懸念点・未決事項
- ダークテーマとシークレット配色（`#2b2d31`）が近く、見分けにくくなる。シークレット側に、ダークテーマでも分かる区別（ラベル、枠線、一覧の 🔒 など）をどこまで頼るか、実機で決める。
- ダークテーマはミニマル方針（影・グラデーションなし、色は限定）に沿って、色数を増やさずに作る。AGENTS.md の「色は…だけに付ける」の記述も合わせて直す。
- 文字サイズは textarea とハイライト層の位置ずれのリスクがある。`px` 単位で、同じ変数を共有し、`line-height` は倍率のまま保つ。
- 設定の値の範囲（間隔 500〜5000ms、文字サイズ 12〜24px）は仮置き。変えたい場合は指示してほしい。
- 設定の `localStorage` キーは `settings`（`memos` とは別）。`sidebarWidth` / `sidebarCollapsed` はそのままで、設定には統合しない。
- 全メモ削除は元に戻せない。確認は 1 回のダイアログで足りるか（二重確認が必要か）は、実装時に判断する。
- バージョンは機能追加なので minor 以上になる見込み（別途 `/version-up`）。
