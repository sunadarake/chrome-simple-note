# 未保存メモがある状態でタブを閉じるときに確認を出す

## 概要
編集中のメモに未保存の変更があり、かつそのメモ種別の「削除の確認」設定がオンのとき、タブを閉じる（リロード・別ページへの移動を含む）とブラウザ標準の離脱確認を出す。独自モーダルはタブの×や Ctrl+W を横取りできないため使わず、`beforeunload` の標準ダイアログにする。その場での保存はできないため、ユーザーは閉じるのをキャンセルして保存するか、そのまま破棄するかを選ぶ。

## 調査結果
- メモ画面は通常のタブ（`src/background.js` が `src/memo.html` を開く）なので、閉じる操作を拾えるのは `beforeunload` だけ。`document` ではなく `window` に登録する必要がある
- `src/memo.js` に未保存判定の材料がある。`lastContent` / `lastCustomTitle` は読み込み・保存時に更新され、`contentInput.value` / `customTitle`（`editingTitle` 中は `titleInput.value`）と比べれば未保存か分かる
- 削除確認の設定は `settings.confirmDelete[kind]`（`normal` / `secret`）。`currentKind()` で種別を取れる
- 保存可能な内容かは `hasSavableContent(content, customTitle)`（`src/memo-store.js`）
- テストは `src/memo.test.js`。`beforeEach` で `document.body.innerHTML = body` を作り直すため、古い `window` リスナーが残る。`container.isConnected` で古い画面のハンドラを無視する（`initShortcuts` を `root` に登録しているのと同じ考え）

## 実装計画
- [x] ステップ1: `src/memo.js` に `beforeunload` ハンドラを追加する。`currentId` があり、`settings.confirmDelete[currentKind()]` がオン、本文または手動タイトル（タイトル編集中は入力中の値）が保存済みと違い、`hasSavableContent` を満たすときだけ `event.preventDefault()` と `event.returnValue = ''` で標準確認を出す。`root.defaultView`（`window`）に登録し、`container.isConnected` で古い画面のリスナーを無視する
- [x] ステップ2: `src/memo.test.js` に、確認が出る／保存済み・削除確認オフ・内容が空なら出ない、タイトル編集中も未保存として扱う、シークレットメモの設定に従う、のテストを追加する
- [x] ステップ3: `AGENTS.md` の仕様に、未保存時の離脱確認と発火条件（削除確認の設定に従う）を追記する

- [ ] 実機で、変更後にタブを閉じるとブラウザ標準の確認が出て、保存済みなら出ない

## 決定事項
- 方式はブラウザ標準の離脱確認（`beforeunload`）のみ。独自モーダルや閉じるボタンは追加しない
- 条件は「編集中のメモに未保存の変更があり、かつそのメモ種別の削除確認がオン」。内容が空で保存できない状態では出さない
- タイトル編集中の入力も未保存の変更として扱う

## 懸念点・未決事項
- ブラウザ標準ダイアログの文言は「変更が保存されていない可能性があります」などに固定され、「保存しますか？」にはできない。その場で保存する選択肢もない
