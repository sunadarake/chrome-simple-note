# code fence の中を言語を問わず簡易ハイライトする

## 概要
エディタの code fence（```` ``` ````）の中は今、全行が `md-codeblock` の1色になっている。コメント・文字列・数値・キーワードを色分けして、コードを読みやすくする。言語ごとの文法は持たず、js / ts / python / json / html / css / sh / Perl / PowerShell / C / C++ / Go などに共通する簡易ルールで色付けする。

## 調査結果
- `src/markdown-highlight.js`: `highlightMarkdown` が行ごとに処理し、コードブロック内の行は `wrap('codeblock', line)` で1色にしている。開始行の言語指定（```` ```js ````）は見ていない。
- `src/memo.css`: `.md-codeblock`（396〜429行付近の通常配色）と、シークレット／ダークテーマ用の上書き（`.main-content.secret .md-*` と `.container[data-theme='dark'] .main-content:not(.secret) .md-*`、500〜540行付近）が組になっている。新しいクラスも同じ形で2系統ぶん足す必要がある。
- `src/markdown-highlight.test.js`: 「コードブロック」の2件と、「タグを除いた文字列が元と一致する」テストが対象。コードブロック内の期待値を直す。
- エディタは `textarea` の背面に `pre` を重ねる構成のため、ハイライトは色と下線だけにし、太字・斜体・サイズ・文字の増減は使えない（AGENTS.md）。
- AGENTS.md の「色は〜だけに付ける」に、コードの色分けが当てはまらない。仕様を更新する必要がある。

## 実装計画
- [x] ステップ1: `src/markdown-highlight.js` に、コード1行を色付けする `highlightCode(line)` を足す。1か所でしか使わないので別ファイルにはしない。次の順に1回の走査（`matchAll`）で切り出す
  - コメント: `//…` 行末まで、`#…` 行末まで、`/* … */`（同じ行で閉じるものだけ）。`--`（SQL・Lua）は対象外
  - 文字列: `"…"` / `'…'` / `` `…` ``（同じ行で閉じるものだけ。`\"` などのバックスラッシュのエスケープは読み飛ばす）
  - 数値: `\b\d+(\.\d+)?\b` と `0x…`
  - キーワード: 各言語に共通するもの（`if else for while return function def class const let var import from package func fn true false null nil None` など）を1つの正規表現にまとめる
  - それ以外はそのまま（HTML エスケープのみ）
- [x] ステップ2: `highlightMarkdown` を直す。開始・終了の ```` ``` ```` 行は今まで通り `md-codeblock`。中の行は `md-codeblock` で包まずに `highlightCode` の結果にする。文字は増減させない
- [x] ステップ3: `src/memo.css` に `.md-code-comment` / `.md-code-string` / `.md-code-number` / `.md-code-keyword` を足す。色だけ（太字・斜体なし）。通常・シークレット・ダークテーマの2系統ぶん書く。コードブロック内の無着色の文字は、これまでの `.md-codeblock` の色にそろえる（`pre` の親の文字色が違って浮かないよう、必要なら1行ぶんを包む）

  - 閉じていない文字列・コメントには色を付けない
  - 文字列の中の `//` や `#` をコメントにしない

## 決定事項
- 言語を問わない簡易ハイライトにする（言語ごとの文法や、```` ```js ```` の言語指定の判別はしない）
- 色付けの対象は、コメント・文字列・数値・キーワードの4種類
- コメントの記号は `//` と `#` と `/* */` を言語に関係なく有効にする（言語指定を見ないため）

## 懸念点・未決事項
- 複数行にまたがる `/* … */`・三連引用符・ヒアドキュメントは色付けしない（行ごとの処理のため）
- 言語指定を見ないので、`#` を使わない言語（C など）の `#include` はコメント色になる。`//` を使わない言語の URL 中の `//` なども同様に誤判定しうる（文字列の中は除く）
- 共通キーワードの一覧は言語ごとの過不足が出る。HTML / CSS / JSON は、キーワードがほぼ付かず、文字列・数値・コメントが中心になる
- 回答で言語の一覧（Perl・PowerShell・C・C++・Go を含む）が選ばれたが、簡易ハイライトを選んでいるので、言語ごとの対応は計画に含めていない。言語別の対応が必要なら教えてほしい
