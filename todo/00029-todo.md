# メモ画面のキーボードショートカットとアンドゥを追加する

## 概要
メモを開いている間、Ctrl+C でコピー、Ctrl+S で保存、Ctrl+U でアンドゥ、Delete で削除できるようにする。Chrome の既定ショートカット（Ctrl+S のページ保存、Ctrl+U のソース表示など）は、この画面でだけ止める。アンドゥは新しく独自の履歴を追加し、Ctrl+U で本文を複数回前の状態に戻せるようにする。

## 調査結果
- `src/memo.js` はキーボード操作をほとんど持たない。例外はタイトル入力の Enter / Escape（409〜412行）だけ。
- コピーは `copyContent`（283〜287行）が `contentInput.select()` で本文全体を選択してから、`main.js` から渡される `copy`（`document.execCommand('copy')`）を呼ぶ。保存は `saveMemo`（213〜222行）、削除は `deleteMemo`（224〜236行）。
- 本文の変更は `contentInput` の `input` イベント（406行）から `handleContentInput`（261〜265行）を通り、ハイライト更新・タイトル更新・自動保存の予約を行う。
- 自動保存との差分判定に `lastContent` と `lastCustomTitle`（84〜87行）を使っている。メモを切り替える `loadMemo`（115〜131行）で更新される。
- 設定パネルを開くと `setSettingsOpen`（304〜310行）が `.main-header` と `.editor` を隠す。ショートカットを有効にする範囲は、この「エディタが表示されているか」で判定できる。
- `src/main.js` は `copy`、`confirm`、`download` を注入している（4〜20行）。テストでは `src/memo.test.js` の `start()` が偽の `copy` と `confirm` を渡している。
- Chrome の既定動作として、Ctrl+S はページ保存、Ctrl+U はソース表示を開く。ハンドラで `preventDefault()` しないと拡張機能の画面から離れる。
- タイトルは `titleInput` の Enter かフォーカス外れで確定する（`endTitleEdit` 156〜166行）。保存ボタンをクリックした場合は、先に blur でタイトルが確定してから保存される。
- 既存のアンドゥ機構はない。textarea の標準 Ctrl+Z はブラウザ側で動くが、独自の履歴とは連動していない。

## 決定事項
- Ctrl+C は「選択優先、なければ本文全体」にする。
- Ctrl+U のアンドゥは独自の多段履歴にする（直前の1回だけではない）。
- アンドゥの対象は本文のみ。手動タイトルは対象外。
- Delete キーは、本文やタイトルを入力中でも常にメモ削除にする。
- ショートカットはエディタ表示中のみ有効。設定パネル・ヘルプ表示中は無効。
- ヘルプ画面をキーボードで開くショートカットは用意しない（TODO 030 の方針）。

## 懸念点・未決事項
- Delete キーを入力中でもメモ削除にすると、削除確認がオフのときに誤操作でメモが失われる。既定の「確認する」を維持する前提だが、実装時に注意する。削除のアンドゥは用意しない。
- アンドゥは本文のみで、メモ削除・タイトル変更・インポートは戻せない。メモを切り替えると履歴も消える。
- ブラウザ標準の Ctrl+Z は残るため、Ctrl+Z と Ctrl+U で戻る単位が異なる可能性がある。Ctrl+Z による変更も `input` イベントとして履歴に積まれる想定。
- Mac の Cmd キーは今回の対象外（Ctrl のみ）。必要なら別途対応する。
- TODO 030（ヘルプ画面）はこの TODO の `SHORTCUTS` を一覧表示に使うため、先にこの TODO を完了させる。
- ステップ6は `src/main.js` ではなく `src/memo.js` の `initMemoApp` 内で `initShortcuts` を呼んだ。コピー・保存・削除・アンドゥの処理が `initMemoApp` の内部関数で、`main.js` からは渡せないため。リスナーは文書ではなく `.container` に登録している。
