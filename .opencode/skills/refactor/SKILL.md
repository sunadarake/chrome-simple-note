リファクタリングしてください。対象: `$ARGUMENTS`

## 対象の決め方
- 引数があれば、そのファイル・ディレクトリ（スペース区切りで複数可）だけを対象にする
- 存在しないパスがあれば、何も変更せずに報告して止まる
- 引数がなければ、`git diff HEAD --name-only` のファイルを対象にする
- それも空なら、`git diff HEAD~1 --name-only` のファイルを対象にする
- どちらも空なら「対象なし」と報告して止まる
- 引数で指定したファイルに未コミットの変更があれば、先にコミットするよう促して止まる

## 検証方法
- AGENTS.md / AGENTS.md / package.json / Makefile などから、テストやビルドのコマンドを探す
- 見つからなければ「検証なし」と報告し、すべての変更を 🟡 として扱う

## 進め方
1. 対象のコードを読み、リファクタリングの候補を洗い出す
2. 🟢 を1件ずつ変更し、そのたびに検証する。失敗したらその1件だけ戻して 🟡 に回す
3. 🟡 は実行せず、番号つきの一覧にして報告する
4. 利用者が選んだ番号だけ実行する（実行後は同じく検証する）

## 分類
- 🟢 実行する（安全）
  - 未使用の変数・関数・import の削除
  - 同じファイル内の重複コードの共通化
  - コードを読めば分かることを繰り返すだけのコメントの削除
  - 動作を変えない関数の分割
  - 同じファイル内の命名の統一
- 🟡 確認する（実行しない）
  - ファイルをまたぐ変更
  - 公開関数の名前・引数の変更
  - 挙動が変わりうる変更
  - テストのない箇所
  - 安全か迷うもの

## 報告（箇条書き、全体で20行以内、🟢 → 🟡 の順）
- `🟢 ファイル:行 - 実行した内容`
- `🟡 N. ファイル:行 - 案（理由）`

## ルール
- 対象の外は、気づいても触らない
- 1回で大規模に変えない。動作は変えない
- 迷ったら 🟡 にする
- 戻すときは `git checkout -- <ファイル>` で対象ファイルだけを戻し、利用者の他の変更を消さない
- テストを弱めたり無効にしたりして通さない
