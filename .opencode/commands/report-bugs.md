既知の不具合を調べて報告してください。対象の指定: `$ARGUMENTS`

## 調べること
- `todo/` の「懸念点・未決事項」と、`plans/` のレビューで挙がった問題を読む
- `FIXME:` / `BUG:` / `XXX:` コメントを Grep で探す
- `git log --oneline -30` の `fix:` を見て、同じ箇所が繰り返し直されていないか確認する

## 報告内容(各項目は箇条書きで、全体で20行以内)
1. **不具合の一覧**：ファイル名(またはファイル:行番号)つきで、症状を1行で書く
2. **影響の大きさ**：各項目を 高 / 中 / 低 で示す(動かない・データが壊れる=高)
3. **直す順番**：先に直すとよい順に3項目以内。理由を一言添える

## ルール
- 専用の不具合リストがない場合は、上の調査範囲で見つかったものだけを報告し、取りこぼしがありうると一言添える
- 確認できていないことは推測せず「不明」と書く。再現を試していないものは「未再現」と書く
- 不具合は修正せず、報告のみにする
- コードやファイルは変更しない
