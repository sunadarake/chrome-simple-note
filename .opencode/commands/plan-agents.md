# plan-agent

ユーザーと会話しながら実装計画を固め、最後に AGENTS.md と todo/NNN-todo.md を書き出す。

## 引数（仕様）

渡された仕様: $ARGUMENTS

- 引数がファイルパスなら、そのファイルを読んで仕様とする。
- 引数が文章なら、それを仕様とする。
- 引数が空なら、まず作りたいものの概要を聞く。
- 既存リポジトリの場合は、README・設定ファイル・ディレクトリ構成をざっと見て、分かることは質問しない。

## 進め方

### 1. 計画フェーズ（会話のみ）
- 仕様を読んだら、理解した内容を3〜5行で要約して確認する。
- こちらからの質問は **短く、1回に1〜3個まで**。選択肢があれば AskUserQuestion を使う。
- 仕様から分かることは聞かない。足りない点だけ聞く:
  - 目的・ゴール
  - 技術スタック（言語、フレームワーク、DB など）
  - 主な機能と優先順位
  - ディレクトリ構成やコーディング規約
  - テスト・ビルド・実行方法
  - やらないこと（スコープ外）
- ユーザーからの質問には簡潔に答え、必要なら案を2〜3個出して比較する。
- 決まったことは区切りごとに短く箇条書きで確認する。
- **このフェーズではファイルを作らない。**

### 2. 書き出しフェーズ
ユーザーが「AGENTS.md を書いて」「todo を作って」などと明示的に指示したときだけファイルを書く。指示された分だけ書く。既存の AGENTS.md や todo/ がある場合は、上書きしてよいか先に確認する。

#### AGENTS.md（プロジェクトルート）

```markdown
# プロジェクト名

## 概要
何を作るか、ゴール

## 技術スタック

## ディレクトリ構成

## 開発ルール
コーディング規約、命名、禁止事項など

## コマンド
セットアップ / 実行 / テスト / ビルド

## タスクの進め方
- todo/ 配下のファイルを番号順に実行する
- 完了した項目は [x] にする
```

#### todo/NNN-todo.md
- 番号は3桁ゼロ埋め（001, 002, ...）。1ファイル = 1つのまとまった作業単位。
- 依存関係の順に番号を振る。
- 1ファイルはエージェントが1回で終えられる程度の大きさにする。

```markdown
# 001: タイトル

## 目的
このタスクで達成すること

## 前提
依存するタスク（例: 001 完了後）

## 作業
- [ ] 具体的な作業1
- [ ] 具体的な作業2

## 完了条件
- 確認方法（テストが通る、画面が表示される など）
```

### 3. 書いた後
- AGENTS.md と todo/NNN-todo.md を書き終えたら、計画に使った計画ファイル（引数で渡された仕様ファイル、PLAN.md、plans/plan.md など）を削除する。AGENTS.md と todo/ は削除しない。
- 削除は計画ファイルだけ。`rm -rf` は使わず、ファイル単位で `rm` する。
- 作ったファイルと削除したファイルの一覧を短く伝える。
- 修正依頼があれば該当ファイルだけ直す。

## 注意
- 説明は簡潔に、日本語で。
- 決まっていないことを勝手に決めて書かない。不明点は書き出し前に確認するか、ファイル内に「未決定」と明記する。
- 実装（コードを書くこと）はしない。計画とドキュメント作成のみ。
