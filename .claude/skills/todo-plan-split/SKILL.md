## 依頼内容
$ARGUMENTS

## 最新のTODOファイル（最大5件）
!`ls todo/ | tail -5`

## 手順
1. 依頼内容を理解し、関連するコードを Glob / Grep / Read で調査する
2. 依頼を独立して実装できる単位に分け、TODO の一覧(タイトルと1行の概要)を先に示す
3. TODO ごとに順番に、不明点や判断が分かれる点を AskUserQuestion で質問して回答を待つ（推測で進めない）
   - 質問は TODO ごとに分けて行い、複数の TODO をまとめて聞かないこと
   - 依頼文から読み取れない仕様（挙動・出力形式・対象範囲・エッジケースなど）も聞く
   - ただし、答えによって実装が変わる点だけに絞る。聞くことがない TODO は質問を省く
4. 回答を踏まえて TODO ごとに実装計画を立てる
5. 既存ファイルの最大番号に +1 した番号から、TODO の数だけ連続で3桁ゼロ埋めの番号を決める（ファイルがなければ 001）
6. `todo/NNN-todo.md` を TODO ごとに新規作成する（例: 既存が 002 までで TODO が2件なら `todo/003-todo.md` と `todo/004-todo.md`）
   - TODO 間に依存(先に終えるべきもの)があれば、番号の順序に反映し、「懸念点・未決事項」に書く

## TODOファイルの形式
# <タイトル>

## 概要
何を・なぜ実装するか

## 調査結果
関連ファイルと現状の構成

## 実装計画
- [ ] ステップ1: 具体的な作業内容（対象ファイル）
- [ ] ステップ2: ...

## テスト・確認方法
- [ ] ...

## 決定事項
質問への回答で決まったこと

## 懸念点・未決事項
- ...

## 注意
- 計画の作成のみ行い、コードの実装はしないこと
- 質問は調査後に行い、コードを読めば分かることは聞かないこと
- 作成後、各ファイルのパスと計画の要約を報告すること
