# LLMs.md 作成・更新

LLM のプロンプトにそのまま貼れる、プロジェクトの使い方ドキュメント `LLMs.md` をプロジェクトのルートに書く。

README.md は人間向け、LLMs.md は LLM が正しくコードを読み書き・実行するための資料として使い分ける。

## 手順

1. プロジェクトを調べる
   - 既存の `LLMs.md` があれば読む（あれば「更新」、なければ「新規作成」）
   - `README.md`、`AGENTS.md`、`CLAUDE.md` があれば読む
   - ディレクトリ構成、設定ファイル（`package.json`、`pyproject.toml`、`Makefile` など）、エントリポイントを確認する
   - 各コマンド・スクリプトの先頭コメントと `-h` / `--help` の処理を読み、引数・オプションをコードで確認する
2. 下の「構成」どおりに `LLMs.md` を書く
3. 書いたコマンド・パス・オプションが実在するかを確認する

## 構成

次の見出しを、この順番で使う。該当がない節は省く。

```markdown
# プロジェクト名

## 概要
## ディレクトリ構成
## セットアップ・実行
## コマンド・API
## 規約・制約
```

### 概要
- 何をするプロジェクトかを 2〜3 行で書く。

### ディレクトリ構成
- 主要なディレクトリ・ファイルだけを、ツリーまたは表で書く。各行に役割を 1 行で添える。

### セットアップ・実行
- ビルド、インストール、実行、テストのコマンドを、コードブロックで書く。

### コマンド・API
- コマンド・関数・API ごとに、名前、用途、引数・オプション、使用例を表またはコードブロックで書く。
- 既定値、必須かどうか、出力形式が分かるものは書く。

### 規約・制約
- コードを書くときに守るルール（言語、命名、コメントの言語、依存関係の方針など）を箇条書きで書く。
- やってはいけないこと、ハマりやすいことも書く。

## 書き方のルール

- 日本語で、短い文で書く。
- LLM が誤解しないよう、曖昧な表現を避け、コマンドは実行できる形で書く。
- コードから確認できた内容だけを書く。推測で書かず、不明点は作業後にユーザーへ伝える。
- 絵文字、バッジ、目次、宣伝文句は付けない。
- AGENTS.md や README.md の内容を丸ごと写さず、LLM が使うのに必要な情報に絞る。
- 秘密情報（トークン、パスワード、`.env` の値）は書かない。

## 既存 LLMs.md を更新する場合

記述を 1 つずつ今のコードと照らし合わせ、変わった点だけ直し、なくなった記述は削除、新しいものは追記する。

## 作業後の報告

変更点を短く箇条書きで伝える（追加・削除・修正・要確認）。
